# RFC: articulated LED desk lamp — fast-agent implementation queue

This is an execution brief for a fast coding agent, not a product contract, a delivery
calendar, or proof that a named capability already exists. Once a lot is merged, living
truth belongs in the relevant how-to and reference pages. The current coverage pages
remain authoritative until an implemented, qualified path and its evidence change them.

The goal is one deliberately bounded, inspectable articulated LED desk-lamp demo: a
human can see the product story and inspect distinct mechanics, thermal, circuit, impact
and decision evidence for one exact project revision. It is not a certification claim, a
manufactured-product release, generic multiphysics, or a promise of modal analysis.

Before code, read the [human input gates](00-human-input-gates.md). They separate work
Grok may consume automatically from physical and consequential decisions that remain
human-owned. Missing inputs do not justify defaults; they park only the dependent live
evidence lot, not unrelated generic implementation.

## Non-negotiable boundaries

- An engine returns technical facts. CalculiX, OpenModelica and ngspice are engines;
  none is an oracle or an L5 decision. SysON constraint evaluation owns reviewed
  requirement comparison; an explicit human record owns the consequential decision.
- The agent proposes and executes registered operations only. It does not choose a
  native tool, command, solver deck/netlist envelope, runtime/image alias, path, mesh
  setting, provider credential, raw SysML, or raw SysON request.
- Mechanics consumes exact canonical part STEP where its method requires geometry; a
  `cad-model`, preview, parser success or private isolated output is not a substitute.
- New lamp data may flow through an existing qualified surface. A new analysis family,
  metric, unit, source grammar, lowerer, worker output, recovery rule or evaluation
  projection is shared capability work: closed contract through WAL/replay, never an
  extra catalog field or a lamp-specific branch.
- `pass` is an L4 evaluation, not L5. `unavailable`, `unresolved`, `error`,
  `provisional`, `documentary`, `unverified`, `demo`, `TRACE GAP` and `UNLINKED` stay
  literal. No screen, solver exit or successful queue action fills a missing link.
- This queue makes no modal promise. Do not add modal schemas, operations, catalog rows,
  tests or documentation under the banner of the lamp demo.

## Automatic continuation and stop rules

After a green lot: commit only that lot, update the Progress journal, and start its next
allowed dependency automatically. Do not wait for permission between green, bounded
lots. A defect discovered later belongs to the earliest owning lot; make a small causal
follow-up there rather than hiding compatibility logic downstream.

Stop and request a human decision—not an invented default—when:

- the lamp's intended use, physical assumptions, criterion threshold, material, source
  value, geometry basis, circuit scenario, impact condition or accepted consequence is
  not already explicitly reviewed;
- an MRTR or L5 decision is required;
- a new metric needs a SysON write → extract → evaluate unit proof, or criteria do not
  have defined comparison semantics;
- the method would require raw solver/netlist/provider arguments, an arbitrary source
  escape hatch, unpinned runtime/image, a noncanonical geometry substitute, or a
  lamp-specific execution branch; or
- engine/isolation/oracle recovery is ambiguous. Preserve state and report `unresolved`
  or `error`; never redispatch a non-idempotent call to manufacture a cleaner outcome.

An ordinary local coding failure is not a human gate: diagnose it against the current
lot, apply the smallest causal repair, and rerun focused validation. An unrelated dirty
worktree failure is external: preserve it and use an isolating check if possible.

## Worktree, commits and proportionate validation

Before every lot inspect `git status --short`, branch, relevant diff and the prior
handoff. Stage explicit paths only; never `git add -A`, a broad formatter, a lockfile
refresh for tidiness, or someone else's change. Default to one coherent commit per
completed lot (`feat(behave): ...`, `fix(behave): ...`, or `docs(behave): ...`). Audit
`git diff --cached --name-only` and `git diff --cached --check` before each commit.
Never reset, rebase, force-push, amend another author, push, or publish externally
without explicit authorization.

Each lot runs its smallest causal checks: contract/parser checks for an input contract;
lowering, worker manifest and output-validator checks for an engine path; WAL/replay and
evaluation-capture checks for a persisted-proof path; link/claim checks for docs. Record
commands actually run and what each proves. Do not run the global repository gate after
each lot. Lot 10 alone runs the required integrated checks, including `deno task
check`
and `deno task check:ui` only if UI sources changed, plus all affected focused and
persisted replay checks.

## Definition of done

The core demo is complete only when one exact lamp project has an inspectable bounded
question, server-owned architecture/parameter authority, exact geometry where needed,
distinct mechanical/thermal/electrical evidence at their true authority levels, one
reviewed cross-domain change with explicit impact, a read-only Workbench projection of
persisted facts, and human decisions only where actually recorded. A static result
cannot prove impact; a documentary Modelica run cannot be called a thermal requirement
verdict; ngspice cannot become an oracle; a UI card cannot create proof.

Each vertical independently closes review → sealed inputs → qualified execution →
captured observations → applicable evaluation → WAL/replay. Otherwise the demo remains
blocked at its precise literal state. The final branch reconciles living
coverage/how-to/reference pages with implemented behavior and explicit exclusions.
